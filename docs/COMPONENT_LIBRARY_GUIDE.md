# 组件库与主应用关联功能说明

## 功能概述

本系统支持主应用（NNIM）与组件库的多对多关系管理。每个组件库版本可以关联到多个主应用版本，方便追踪和管理依赖关系。

## 使用方法

### 1. 上传组件库 dSYM

当上传组件库（非 NNIM）的 dSYM 文件时：

1. 系统会自动识别这是组件库
2. 在上传成功后的表单中，会显示"关联主应用版本"多选下拉框
3. **必须至少选择一个**主应用版本（从已上传的 NNIM 版本中选择）
4. 可以选择多个主应用版本，表示该组件库支持这些版本
5. 可选填写备注信息

### 2. 编辑组件库信息

在管理页面的"组件库"标签页中：

1. 点击"编辑"按钮
2. 可以修改版本号、关联的主应用版本（多选）和备注
3. 至少需要选择一个关联的主应用版本

### 3. 查看关联关系

#### 在主应用标签页
- 每个主应用版本会显示"关联组件库"列
- 可以看到哪些组件库版本关联到这个主应用版本

#### 在组件库标签页
- 每个组件库会显示"关联主应用版本"列
- 以绿色标签显示所有关联的 NNIM 版本
- 支持显示多个版本标签

## 数据库结构

### dsym_info 表新增字段

```sql
related_app_version TEXT  -- 关联的主应用版本列表（JSON 数组格式）
```

- 对于主应用（NNIM），此字段为 NULL
- 对于组件库，此字段存储 JSON 数组格式的主应用版本列表
- 示例：`["5.12.0", "5.12.3", "5.13.0"]`

## API 接口

### 上传 dSYM
```
POST /api/dsym/upload
```

### 更新 dSYM 信息
```
PUT /api/dsym/:uuid
Body: {
  version: string,
  notes?: string,
  relatedAppVersions?: string[]  // 组件库关联的主应用版本列表
}
```

## 前端类型定义

```typescript
export interface DSYMInfo {
  id: number;
  uuid: string;
  appName: string;
  version: string;
  buildNumber?: string;
  architecture: string;
  filePath: string;
  fileSize: number;
  notes?: string;
  relatedAppVersions?: string[];  // 关联的主应用版本列表（用于组件库）
  uploadTime: string;
}
```

## 使用场景

1. **版本追踪**：快速了解某个组件库版本支持哪些主应用版本
2. **依赖管理**：查看某个主应用版本使用了哪些组件库版本
3. **符号化分析**：在分析崩溃日志时，可以根据主应用版本找到对应的组件库符号文件
4. **多版本支持**：一个组件库版本可以同时支持多个主应用版本，减少重复上传

## 注意事项

1. 上传组件库时必须至少选择一个关联的主应用版本
2. 建议先上传主应用 dSYM，再上传组件库 dSYM
3. 可以选择多个主应用版本，表示该组件库支持这些版本
4. 如果主应用版本被删除，关联的组件库记录不会自动删除，但关联关系会失效
5. 数据库中使用 JSON 数组格式存储多个版本，兼容旧的单版本数据
