# 共用组件库

导航与页面统一命名为“组件库”。组件库属于系统资源，同一系统下的多个产品线可绑定同一个库；当前执行器为 iOS Podx / CocoaPods，Android 的 Maven / Gradle 组件适配尚未实现，不开放跨系统绑定。

## 使用方式

1. 管理员进入“应用接入”，在目标 iOS 应用点击“选配服务”。
2. 启用“组件库（Podx）”，在“共用组件库”中选择已有库。例如 NN 和另一个产品线均选择“NN · iOS 组件库”。
3. 保存后，“组件库”页会显示库名称、共用应用和同一份组件版本。服务开关仍独立：绑定库不会自动启用服务。

新产品线保留自己的空库。存量组件留在原有库中，不自动合并同名版本；切换绑定后仍可切回原库，原记录不会删除。每个应用当前绑定一个库，一个库可供多个产品线使用。

## 共享与独立配置

| 范围 | 行为 |
| --- | --- |
| 组件列表、版本、Podspec、Nexus 产物、Specs 工作副本 | 按选定库共享；发布的新版本写入同一库 |
| Nexus 地址及认证、私有 Specs 源 | 由库来源产品线的 podx / mgit 配置维护；消费方不复制或返回库凭据 |
| 主工程、Git 命名空间、组件源码协作仓库、目标分支、Jenkins Job | 仍按当前产品线；导出的 Podx 配置使用共享 Specs 源 |
| dSYM、主应用版本关联、Workflow 任务、构建及发布历史 | 保持原有产品线范围，本次不合并 |
| AI 组件依赖分析 | 查询选定库，并返回库及共用应用范围；绑定关系不代表该产品已经使用某一版本 |

产品线配置页中的 Nexus 与私有 Specs 字段维护该产品线原有库。若该产品线应用绑定其他库，运行时采用来源库资源。来源产品线停用时，依赖它的库不可继续使用，不会自动回退到另一个库。

共用库已有版本不可覆盖或删除，页面和 API 均限制；请发布新版本，让各产品线分别选择升级。主工程分支同步成功或失败不会修改共用组件的发布状态或来源分支。单产品线使用的库维持已有维护方式。

组件请求及其派生后台发布固定使用请求开始时的库，过程中修改应用绑定不会把进行中的发布重定向到另一个库。变更绑定不会自动同步或推送任何产品工程，需要通过现有工程同步操作使已生成的 Podx 配置更新。

## 数据兼容与验证

`component_libraries` 保存平台和配置来源，`platform_applications.component_library_id` 保存绑定。历史 `pods_components.product_line_id` 保留为库的存储分区，避免重写历史版本和标识；它不再意味着只有该产品线能查询这些组件。迁移可重复执行。

后端测试使用临时数据库验证共用、切换、迁移、跨系统拒绝、仓库资源与主工程分离、AI 查询、共享版本保护、同步状态隔离和进行中请求的目标固定。浏览器使用隔离 API fixtures 验证名称、选择入口和跨产品线显示，不访问真实 Nexus、Git 或 Jenkins。

```sh
npm run check
npm run build
node scripts/test-component-library-ui.mjs
node scripts/test-application-services-ui.mjs
```
