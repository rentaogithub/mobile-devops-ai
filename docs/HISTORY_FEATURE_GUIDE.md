# 符号化历史记录功能说明

## 功能概述

系统会自动保存每次符号化的崩溃日志，并按照主应用版本进行分类存档。用户可以随时查看历史记录，方便追溯和对比不同版本的崩溃情况。

## 核心特性

### 1. 自动保存
- ✅ 每次符号化成功后自动保存记录
- ✅ 记录包含原始日志、符号化后的日志、使用的 dSYM UUID
- ✅ 自动识别主应用版本（NNIM）
- ✅ 无需手动操作，完全自动化

### 2. 版本分类
- 📁 按主应用版本自动分组
- 📊 每个版本显示记录数量
- 🔍 支持按版本查看历史记录
- 📈 提供统计信息

### 3. 详细信息
每条历史记录包含：
- 主应用版本
- 符号化时间
- 崩溃类型（如果有）
- 崩溃原因（如果有）
- 使用的 dSYM UUID 列表
- 原始崩溃日志
- 符号化后的日志
- AI 分析结果（如果有）

### 4. 权限管理
- 👀 **所有用户**：可以查看历史记录
- 👑 **管理员**：可以删除历史记录

## 使用方法

### 查看历史记录

1. 点击顶部导航栏的"历史记录"
2. 系统显示所有版本的历史记录
3. 点击版本展开查看该版本的所有记录
4. 每条记录显示：
   - 符号化时间
   - 崩溃类型（如果有）
   - 使用的 dSYM UUID

### 查看详情

1. 在历史记录列表中，点击"查看详情"按钮
2. 弹出详情对话框，显示：
   - 完整的版本信息
   - 符号化时间
   - 崩溃类型和原因
   - 使用的所有 dSYM UUID
   - 完整的符号化后的日志

### 删除记录（管理员）

1. 管理员登录后
2. 在历史记录列表中，点击"删除"按钮
3. 确认删除
4. 记录被永久删除

## 技术实现

### 数据库表结构

```sql
CREATE TABLE symbolication_history (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  app_version TEXT NOT NULL,           -- 主应用版本
  crash_type TEXT,                     -- 崩溃类型
  crash_reason TEXT,                   -- 崩溃原因
  original_log TEXT NOT NULL,          -- 原始崩溃日志
  symbolicated_log TEXT NOT NULL,      -- 符号化后的日志
  used_uuids TEXT NOT NULL,            -- 使用的 UUID 列表（JSON）
  ai_analysis TEXT,                    -- AI 分析结果（JSON）
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

### 自动保存流程

1. 用户上传崩溃日志并选择 dSYM
2. 系统执行符号化
3. 符号化成功后：
   - 提取主应用版本（优先 NNIM）
   - 保存原始日志和符号化后的日志
   - 记录使用的所有 dSYM UUID
   - 保存到数据库
4. 返回符号化结果给用户

**响应：**

```json
        "createdAt": "2025-01-15T14:30:25Z"
```

#### 根据版本获取历史记录
```
GET /api/history/version/:version
```

```
GET /api/history/:id
```

#### 删除历史记录（管理员）

```

```

```json
  }

```

## 使用场景

### 场景 1：追溯历史崩溃
**问题**：某个版本的崩溃日志之前符号化过，现在想再看一次。

**解决**：
1. 进入"历史记录"页面
2. 找到对应的版本
3. 查看该版本的所有历史记录
4. 点击"查看详情"查看完整日志

### 场景 2：对比不同版本
**问题**：想对比 5.12.0 和 5.11.0 的崩溃情况。

**解决**：
1. 进入"历史记录"页面
2. 展开 5.12.0 版本，查看崩溃记录
3. 展开 5.11.0 版本，查看崩溃记录
4. 对比崩溃类型和原因

### 场景 3：统计崩溃频率
**问题**：想知道哪个版本的崩溃记录最多。

**解决**：
1. 进入"历史记录"页面
2. 查看每个版本的记录数量标签
3. 或调用统计 API 获取详细数据

### 场景 4：清理旧记录（管理员）
**问题**：历史记录太多，想删除一些旧的记录。

**解决**：
1. 管理员登录
2. 进入"历史记录"页面
3. 找到要删除的记录
4. 点击"删除"按钮
5. 确认删除

## 数据管理

### 存储位置
- 数据库文件：`dSYMTool-data/database.sqlite`
- 表名：`symbolication_history`

### 数据备份
建议定期备份数据库文件：
```bash
cp dSYMTool-data/database.sqlite dSYMTool-data/database.backup.sqlite
```

### 数据清理
如果需要清空所有历史记录（管理员）：
```bash
# 调用 API
DELETE /api/history/clear/all
```

或直接操作数据库：
```sql
DELETE FROM symbolication_history;
```

## 性能优化

### 索引优化
系统已为以下字段创建索引：
- `app_version`：加快按版本查询
- `created_at`：加快按时间排序

### 查询优化
- 列表查询：只返回必要字段
- 详情查询：按需加载完整日志
- 分组查询：使用数据库分组功能

### 存储优化
- 日志压缩：考虑对长日志进行压缩存储
- 定期清理：建议定期清理 3 个月以上的旧记录
