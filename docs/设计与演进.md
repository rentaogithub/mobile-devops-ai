整理日期：2026-09-08。本文集中保留未完成设计、演进优先级和验收条件；[平台架构](平台架构.md)与[功能文档](平台功能.md)描述当前代码。历史实施步骤、示例补丁及机器快照通过 Git 历史追溯，不再作为当前操作手册。

规范依据：[OpenSpec 项目](../openspec/project.md)、[黑盒回放规范](../openspec/specs/ios-black-box-recording-replay/spec.md)、[录制编排变更规范](../openspec/changes/formalize-recording-orchestration/specs/ios-black-box-recording-replay/spec.md)。交付勾选状态只维护在[任务台账](../openspec/changes/formalize-recording-orchestration/tasks.md)，本次文档合并未更改状态或重新认证历史验收。

## 1. 回放编排的统一约束

采用“显式录制来源 → 持久草稿 → 受控 DSL → 校验/编译 → 执行/证据”的设计；不可变发布版本与正式质量任务绑定是待补齐的生命周期。保留既有执行引擎，资产化作为独立业务层加入。详细模型、API 目标和并发方案见[OpenSpec 设计](../openspec/changes/formalize-recording-orchestration/design.md)。

- **黑盒边界：**依赖真机/WDA 的 Tap、Swipe、Input、Keyboard、Source、Screenshot 等能力，不要求向 App 注入测试 SDK 或修改 App 源码。录制观察需人工筛选/补标，不能把屏幕观察等同于已知输入事件。
- **唯一事实源：**步骤、画布和低代码视图投影同一 DSL；连线修改节点跳转，不建立另一套独立图模型。不能完整图形化的合法结构保留为低代码节点，禁止静默删除或改写。
- **有界执行：**顺序执行、显式条件与失败分支、最大重试与总超时；禁止自由环路和无限循环。动作按前置等待 → 定位 → 执行 → 后置验证 → 分支推进。
- **受控语言：**仅 JSON 兼容的数据与字符串变量；禁止任意 JavaScript/Python/Shell、文件/数据库操作、任意网络请求、动态安装代码和后台线程。变量来自受控运行输入、默认值和环境映射，元素文本提取属后续扩展，不提供跨流程全局可变状态。
- **可解释定位：**保留语义、归一化/控件相对坐标、屏幕尺寸、截图/Source 和元素矩形。优先 accessibilityId，再 name/label/text、type/上下文，同名时参考录制坐标，最后坐标兜底并显示不稳定警告。
- **证据要求：**节点记录实际定位策略、目标与执行坐标、WDA 标签、条件匹配/等待、重试及分支、动作前后截图与 Source。条件 false 可走显式分支，单节点失败不必然等于流程最终失败。
- **权限与敏感值：**按项目/应用/角色校验资产与执行，敏感运行输入不进入草稿、版本、审计、任务结果、运行 JSON 或日志。截图/Source 的页面内容另需脱敏与访问控制，不能因 JSON 只存输入名称就声称全面脱敏。

运行状态与错误码需保持稳定、可定位：`RUN_CANCELLED`、`PROCESS_INTERRUPTED`、`NODE_TIMEOUT`、`ACTION_TIMEOUT`、`TARGET_NOT_FOUND`、`WDA_SOURCE_TIMEOUT`、`WINDOW_SIZE_UNAVAILABLE`、`SNAPSHOT_SOURCE_UNAVAILABLE`、`VARIABLE_MISSING`、`FLOW_FAILURE_END`、`TRANSITION_LIMIT`。后端中断按 `PROCESS_INTERRUPTED` 收尾，不自动恢复执行。

新增节点必须同时具备 Schema/兼容定义、静态校验、编译语义、执行/超时/取消实现、画布投影或低代码降级、字段说明、证据定义、测试与真机验收，再更新使用说明。不能只做页面节点或执行器分支就宣称完整支持。

<a id="increment-a"></a>

## 3. 增量 A：明确来源与持久草稿

对应 BRR-012、013、014；台账 1–8 已勾选，9 未勾选。来源指纹按录制 ID、按序纳入的 ready 步骤 ID、动作与目标负载规范化后计算 SHA-256，不包含截图/Source 文件内容。草稿保存携带 `expectedRevision`，不匹配返回 `409 FLOW_DRAFT_CONFLICT`。

验收条件：

1. 新建编排先确认录制身份、设备、停止时间、所选步骤与指纹，不静默取最近录制；无可用步骤返回 `RECORDING_HAS_NO_SELECTED_STEPS`。
2. 草稿刷新浏览器或重启后仍存在；源步骤/补标变化只提示，不覆盖编辑。显式重置生成新 revision。
3. 同一 revision 的并发保存一成功、一冲突；可重新加载或复制，不丢失编辑。关闭编辑器前保存待写内容。
4. 调试绑定已保存 `draftId + revision`，运行保留身份与证据，不持久化敏感输入值。
5. 补齐指纹、持久化、权限/冲突 API、前端保存和来源变化测试，记录脱敏的请求/响应 ID 与观测结果到对应变更验收记录。

<a id="increment-b"></a>

## 4. 增量 B：安全低代码往返编辑

对应 BRR-014；台账 10–15 未完成。YAML 仅作为 JSON 兼容序列化格式，解析后经过同一 Schema、静态校验器和编译器。

验收条件：

1. 拒绝自定义 Tag、锚点、别名、merge key、可执行表达式和环境变量扩展，返回可读的行列与节点诊断。
2. 同一 DSL 多次格式化字节稳定；覆盖每类节点与条件，YAML 往返后编译图语义一致。
3. 画布与代码共用一个已接受 DSL 状态；解析失败保留原文本、阻止切换覆盖草稿。
4. 不能图形化但合法的结构保持可见、可保存，并在版本链路完成后可发布/执行；移动其他画布节点不改写它。
5. 编辑器提供 Schema 补全、字段说明、格式化和诊断；用编码器、前端切换与语义往返测试证明支持，而不只演示编辑框。

<a id="increment-c"></a>

## 5. 增量 C：不可变版本、正式质检与门禁

对应 BRR-015 至 019；台账 16–25 未完成。目标区分草稿调试与正式质检：后者只能按 `flowVersionId` 加载已发布内容，不接受请求体 DSL 或自由业务计划覆盖。

验收条件：

1. 发布事务完成校验、编译、单调版本分配、DSL/编译图/来源指纹/发布元数据和审计写入；失败无部分版本。测试角色不能发布/回滚，研发与管理员按授权操作。
2. 版本只读；复制/回滚创建新草稿 revision，不改历史。管理员删除为可恢复隐藏，保留版本、运行、证据和审计。
3. 正式 P0 请求绑定存在的用例、流程版本、App 源构建、环境、账号引用/输入映射、设备池或 UDID。敏感值仅在执行时解析，不写 Jenkins 参数和公开产物。
4. Jenkins 使用共享引擎执行精确版本。报告与 Workflow 标明版本、时长、分类和证据 URL；目标结果为 `passed` / `failed` / `infra_failed` / `cancelled`，分别区分业务与设备/WDA 等基础设施故障。
5. CLI 目标退出码 `0/10/20/30/40` 分别表示通过/业务失败/基础设施失败/取消/配置无效；即使失败也保留结果文件。门禁显式验证 `infraFailurePolicy=block/warn/ignore`，不能把基础设施失败统计为业务失败。
6. 兼容历史 DSL、录制、运行及证据；未绑定版本的旧运行标为 `legacy`。保存/发布/回滚/调试/正式运行均有权限和脱敏审计。
7. 真机走完录制 → 补标 → 草稿 → 编辑 → 发布 → 指定版本执行 → 报告；修改草稿后验证旧版本不变，分别注入断言失败、WDA 不可用、取消，并核对门禁与日志无敏感值。

按 A → B → C 推进，任务台账继续作为唯一交付状态来源。历史实现计划中的具体补丁、命令和测试数量不再作为当前实现模板。

<a id="execution-chain"></a>

## 6. 单次组合执行约束

对应 BRR-021；台账 27–31 已勾选，表示已有历史实现/验收记录，本次未重新执行真机验收。

资产可引用前置和后置流程；禁止自引用、传递循环、跨项目、归档或未完成创建的引用，并校验被引用资产的归档操作。一次执行持久化 `pre → main → post` 阶段，前置失败跳过主流程，仍尝试后置清理；记录阶段、节点与证据，仅持久化输入名称。当前阶段读取草稿，与不可变版本执行目标仍有差距。

<a id="platform-evolution"></a>

## 7. 平台演进优先级

| 优先级 | 目标 | 验收依据 |
| --- | --- | --- |
| P0：证据可靠 | 固定产品线/应用/源构建归属，补齐同步完整性、统一权限入口、幂等派发恢复、产物与外部归档追溯、数据库及文件一致恢复 | 代表性构建能追到代码、包、任务、Issue 和门禁；缺失/陈旧证据明确阻断或提示；恢复后证据可打开 |
| P1：变更与修复验证 | 用实际变更范围选择测试，把修复 Commit、新构建、回归执行与原问题关联；完成不可变回放版本与正式质量绑定 | 回归结论指向当前构建及精确流程版本；候选 `verified`、AI 建议或人工关闭不单独证明当前构建修复 |
| P2：发布观察与效果 | 定义发布观察时间窗、版本指标、异常归因、AI 建议采纳与实际结果标签 | 观察有来源/窗口/样本量，区分版本聚合与精确构建；使用量、成功率和真实耗时改善分别衡量 |

Android 下一阶段由真实产品和渠道需求驱动：先验收 APK/Smoke 契约，再评估 AAB/拆分 APK、设备池调度、确定性业务回归、R8/NDK、性能及渠道发布。Bugly/Android Sentry 控制台配置不算数据接入。

继续保持单体模块边界清晰，以实际并发、隔离和可靠性需求决定是否拆服务或引入队列。当前架构图、拓扑与数据流统一维护在[架构文档](平台架构.md)，历史机器数据与测试数字不当作持续有效的验收结论。
