# AI 智能分析功能使用指南

## 功能概述

iOS 崩溃日志符号化系统现已集成OpenAI AI 智能分析功能，可以自动分析符号化后的崩溃日志，提供：

- 崩溃类型识别
- 可能的崩溃原因分析
- 修复建议
- 严重程度评估
- 受影响组件识别
- AI 生成的总结说明

## 如何获取OpenAI API Key

1. 访问OpenAI Platform：https://platform.openai.com/api-keys
2. 登录您的 OpenAI 账号
3. 进入 API Keys 页面
4. 创建新的 API Key
5. 复制生成的 API Key（格式通常为 `sk-xxxxxx`）

## 使用步骤

### 1. 在符号化页面输入 API Key

1. 打开"符号化"页面
2. 在"AI 智能分析（可选）"区域输入您的OpenAI API Key
3. API Key 仅在当前会话中保存，不会被持久化存储
4. 页面刷新后需要重新输入

### 2. 执行符号化

1. 粘贴或上传崩溃日志
2. 选择对应的 dSYM 文件
3. 点击"开始符号化"按钮

### 3. 查看 AI 分析结果

符号化完成后，在结果页面的"AI 智能分析"标签页中查看：

- **崩溃类型**：识别的崩溃类型（如：内存访问错误、程序异常终止等）
- **严重程度**：低/中等/高/严重，使用不同颜色和图标标识
- **受影响组件**：识别受影响的系统组件或模块
- **分析总结**：AI 生成的简短总结
- **可能原因**：列出可能导致崩溃的原因
- **修复建议**：提供具体的修复建议

## 注意事项

### 安全性

- API Key 不会被保存到服务器
- API Key 不会被记录到日志文件
- API Key 仅在内存中保存，页面刷新后清空
- 建议使用 HTTPS 访问系统

### 功能特性

- AI 分析是可选功能，不提供 API Key 时仍可正常使用符号化功能
- AI 分析失败不会影响符号化结果的展示
- 分析结果仅显示当前崩溃日志的分析，不保存历史记录
- AI 分析超时时间为 30 秒

### 错误处理

如果 AI 分析失败，系统会：

1. 显示符号化结果（不受影响）
2. 在 AI 分析标签页显示错误提示
3. 记录错误日志供排查

常见错误：

- **API Key 无效**：请检查 API Key 是否正确
- **AI 分析超时**：请稍后重试
- **网络连接失败**：请检查网络设置
- **响应解析失败**：AI 返回格式异常，请重试

## 示例

### 输入

```
Thread 0 Crashed:
0   MyApp    0x0000000100001234    0x0000000100000000 + 4660
1   MyApp    0x0000000100002345    0x0000000100000000 + 9029
...
```

### AI 分析输出示例

**崩溃类型**：内存访问错误 (EXC_BAD_ACCESS)

**严重程度**：严重 🔴

**受影响组件**：用户界面 (UI)、核心功能

**分析总结**：
应用在主线程发生了内存访问错误。崩溃发生在 MyApp 模块的某个函数中。异常代码：SIGSEGV。建议优先检查内存管理和对象生命周期相关的代码。

**可能原因**：
1. 访问已释放的对象（野指针）
2. 数组越界访问
3. 访问未初始化的指针
4. 内存被意外覆盖

**修复建议**：
1. 使用 Address Sanitizer 检测内存问题
2. 检查对象的生命周期管理
3. 使用 weak 引用避免循环引用
4. 添加边界检查和 nil 判断
5. 在测试环境中重现问题
6. 检查相关代码的最近修改

## 技术细节

### API 配置

系统默认调用 OpenAI Responses API，也支持 OpenAI-compatible 中转站的 Chat Completions API：

- **API 端点**：`https://api.openai.com/v1/responses`
- **模型**：`gpt-5.1`
- **中转站端点**：配置 `OPENAI_API_ENDPOINT` 或 `OPENAI_BASE_URL` 为中转站 `/v1` 地址
- **中转站模式**：配置 `OPENAI_API_STYLE=chat_completions`
- **超时时间**：30 秒
- **Temperature**：0.7
- **Max Tokens**：2000

### 提示词设计

系统使用专业的提示词引导 AI 分析：

- 角色定位：iOS 崩溃日志分析专家
- 分析要求：识别崩溃类型、分析原因、提供建议
- 输出格式：JSON 格式，包含所有必需字段
- 分析重点：关注堆栈信息、异常类型、线程状态等

## 常见问题

### Q: API Key 会被保存吗？

A: 不会。API Key 仅在当前会话的内存中保存，不会被持久化存储，也不会被记录到日志文件。

### Q: AI 分析需要多长时间？

A: 通常在 5-10 秒内完成，最长不超过 30 秒（超时限制）。

### Q: AI 分析失败会影响符号化吗？

A: 不会。AI 分析是独立的可选功能，失败不会影响符号化结果的展示。

### Q: 可以保存 AI 分析结果吗？

A: 当前版本仅显示当前崩溃日志的分析结果，不保存历史记录。您可以手动复制分析内容。

### Q: 支持哪些崩溃类型？

A: 支持所有 iOS 崩溃类型，包括但不限于：
- EXC_BAD_ACCESS（内存访问错误）
- SIGABRT（程序异常终止）
- EXC_BREAKPOINT（断点异常）
- SIGKILL（系统强制终止）
- Objective-C 消息发送错误
- 内存管理错误
- UI 相关错误

## 反馈与支持

如果您在使用 AI 分析功能时遇到问题，请：

1. 检查 API Key 是否有效
2. 确认网络连接正常
3. 查看浏览器控制台的错误信息
4. 查看服务器日志（如果有访问权限）

---

**注意**：AI 分析结果仅供参考，实际问题排查还需要结合具体代码和业务逻辑进行分析。
